Executive Summary

The Voluntarios platform has been through an intense build phase. Since 23 June, 20 changes have been completed and archived, covering the full feature set: authentication via Microsoft Entra ID, role-based access control (admin, nave, general), a survey feedback loop with 24-hour email scheduling, admin backoffice with KPI dashboard and user management, API documentation via OpenAPI/Scalar, typed client generation, improved test coverage (backend >70%, frontend Playwright E2E suite), and a wholesale migration from MariaDB+Supabase REST to Drizzle ORM on Postgres.

The platform works end-to-end in development and staging. The remaining work is deployment. Five deployment changes are open — only one (Upstash Redis for the email queue) is near completion at 88%. The others range from 0–35% and overlap in scope. The most strategic path is getting v2 deployed to Vercel so Fundación Altius officers can test and approve the new features, then deciding the final production hosting setup.

Recently Shipped

Key changes completed in the last week:

  • Survey email scheduler — When a volunteer signs a contract, an email is automatically sent 24 hours later with a link to an anonymous satisfaction survey. The survey pages (star ratings, confirmation) were pulled from a feature branch and wired into the main app.
  • Unified data layer — Replaced three different database access patterns (in-memory, MariaDB, Supabase REST) with a single Drizzle ORM + Postgres approach. Staging and production now run the same code against Postgres, eliminating environment-specific bugs.
  • Admin backoffice — A proper admin interface with a collapsible sidebar, KPI dashboard (charts showing contracts by month, location, corporate/volunteer split), contracts list with pagination and search, user management, and survey management.
  • API documentation & security — Every API endpoint is now validated with Zod, documented via an auto-generated OpenAPI 3.1 spec, and served through an interactive Scalar docs page. Security headers from Helmet and cookie-based auth with CSRF protection are in place.
  • Expanded E2E test coverage — Playwright tests now cover error states (401, 403, 404, 500), CSRF rejection, pagination, sorting, lugar filtering, role enforcement, and a real browser flow that creates a contract end-to-end.
  • Duración/modalidad UI fix — The contract wizard's duration and modality fields were changed from broken checkbox grids to proper radio groups (shadcn RadioGroup), fixing the bug where clicking stored a boolean instead of the selected value.
